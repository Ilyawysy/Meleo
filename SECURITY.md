# Политика безопасности

## Назначение репозитория

Этот репозиторий — очищенный инженерный showcase. В нём намеренно отсутствуют
production credentials, реальные `.env`, приватные домены и часть конфигурации
внешних интеграций. Example-файлы содержат только имена переменных и безопасные
шаблоны.

## Сообщение об уязвимости

Не публикуйте информацию об уязвимости в открытом issue. Передайте владельцу
репозитория приватное сообщение через доступный в GitHub профиль канал связи.

В отчёте укажите:

- затронутый компонент и commit;
- условия и минимальные шаги воспроизведения;
- ожидаемое влияние;
- безопасный proof of concept без реальных пользовательских данных;
- возможный вариант исправления, если он известен.

Не проводите тестирование против production-инфраструктуры и сторонних
аккаунтов без отдельного разрешения.

## Области повышенного риска

- проверка Supabase JWT и lifecycle токенов;
- административная авторизация;
- изоляция данных по `user_id`;
- logout и смена Riverpod scope;
- cursor-based sync и idempotency;
- AI tools, rate limiting и защита внешнего LLM-вызова;
- конфигурация Caddy, Redis и observability.

## Работа с секретами

- Локальные значения хранятся только в игнорируемых `.env`.
- В логи и отчёты нельзя включать JWT, service-role keys, LLM API keys и
  содержимое secure storage.
- При случайной публикации значение необходимо отозвать у провайдера; удаления
  из последнего commit недостаточно — требуется очистка всей Git history.

Поддерживаемые security fixes относятся к текущей ветке `main`. Как
академический прототип, проект не предоставляет SLA по срокам исправления.
