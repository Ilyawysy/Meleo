# Участие в разработке

Meleo поддерживается как академический и портфолио-showcase. Внешние pull
request сейчас не принимаются, но архитектурная обратная связь и сообщения о
воспроизводимых дефектах приветствуются через GitHub Issues.

## Как описать проблему

Укажите:

1. затронутый компонент: `apps/mobile`, `apps/admin`, `services/api` или
   `infra`;
2. шаги воспроизведения;
3. ожидаемое и фактическое поведение;
4. версию ОС и используемого SDK;
5. обезличенный лог без токенов, email и значений `.env`.

## Локальные quality gates

```bash
# Mobile
cd apps/mobile
flutter analyze
flutter test

# Backend
cd services/api
ruff check backend/ --select E9,F63,F7,F82
pytest backend/ -v

# Admin
cd apps/admin
npm run build
```

Изменения миграций проверяются командой `alembic heads`. Существующие файлы в
`services/api/backend/alembic/versions/` не редактируются: изменение схемы
оформляется новой ревизией.

## Требования к изменениям

- Сохраняйте минимальный diff и границы существующих модулей.
- Не добавляйте реальные секреты, `.env`, токены, сертификаты пользователя и
  приватные deployment values.
- Изменения auth, JWT, пользовательской изоляции и sync lifecycle требуют
  отдельного review и целевых тестов.
- Новая зависимость должна иметь понятное назначение и добавляться в
  соответствующий manifest.
- Документация должна различать реализованную функцию, прототип и планируемую
  возможность.

CI в `.github/workflows/ci.yml` выбирает mobile, backend и admin jobs по
затронутым путям.
